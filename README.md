# calibration-decision-demo

Standalone, synthetic-data evaluation of **probability calibration** and
**selective prediction** (abstention by confidence). This repository is a
self-contained demo. It does **not** use production data, does **not**
evaluate LLM training, does **not** claim financial performance, and does
**not** report validated SeqInference (SI) results.

The data are generated by `sklearn.datasets.make_classification`. They are
synthetic.

## Question

If a Gaussian naive Bayes classifier is trained on one partition and then
sigmoid-calibrated on a held-out calibration partition, do the calibrated
probabilities improve proper scores and selective-prediction behavior on an
untouched test partition, relative to the raw model and to a constant
probability baseline?

Proper scores (Brier score and log loss) measure **more than calibration**.
They are sensitive to both calibration (whether predicted probabilities match
observed frequencies) and sharpness (how concentrated the probabilities are).
A perfectly calibrated but uninformative model can lose to a slightly
miscalibrated but more informative one. Reliability diagrams and probability
histograms are therefore reported alongside the scores.

## Methods

- **Data (synthetic):** `make_classification` with `n_samples=10000`,
  `n_features=20`, `n_informative=10`, `n_redundant=5`, `weights=[0.7, 0.3]`,
  `class_sep=0.8`, `flip_y=0.05`.
- **Seeds:** `[42, 43, 44, 45, 46]`. Each seed regenerates the dataset and the
  splits.
- **Partitions:** stratified 60% train / 20% calibration / 20% test, mutually
  disjoint. Observed counts were 6000 / 2000 / 2000 on every seed.
- **Base model:** `GaussianNB`, fit on **training data only**.
- **Calibration:** Platt sigmoid scaling via `CalibratedClassifierCV` on an
  already fitted estimator, using `sklearn.frozen.FrozenEstimator` (scikit-learn
  1.9.1). Fit on **calibration data only**. The frozen wrapper does not refit
  the base model; raw and calibrated test probabilities come from that same
  fitted `GaussianNB`.
- **Baseline:** constant probability equal to the **training** positive-class
  frequency (about 0.31 on these seeds). Calibration-set and test-set labels
  are not used to form the baseline.
- **Evaluation:** **test partition only**. Thresholds were predefined and were
  not chosen or tuned using test results.
- **Confidence:** `max(p, 1-p)`. An example is accepted when
  `confidence >= threshold` for thresholds `[0.50, 0.60, 0.70, 0.80, 0.90]`.
  If the accepted count is zero, accepted accuracy and accepted error rate are
  recorded as `unavailable`.

## Reproduction

Use only this project's virtual environment. Do not install packages globally.
Run the commands from the repository root.

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe -m pytest test_metrics.py -v
.\.venv\Scripts\python.exe demo.py --output-dir results
```

`requirements-lock.txt` pins the environment that produced the checked-in
`results/`. `requirements.txt` lists the direct dependencies without pins.

The plotting backend is noninteractive (`matplotlib` `Agg`).

To repeat the experiment into a separate folder and compare **all published
numerical artifacts** (not a summary subset):

```powershell
$tmp = Join-Path $env:TEMP "calibration-decision-demo-repro"
.\.venv\Scripts\python.exe demo.py --output-dir $tmp
.\.venv\Scripts\python.exe demo.py --compare results $tmp
```

The comparison loads, in full:

- `config.json`
- `all_seeds.json` (per-seed Brier, log loss, accuracy, probability summaries,
  reliability-bin statistics, partition counts, training positive rate, and
  selective metrics: threshold, coverage, accepted count, accepted accuracy,
  accepted error rate)
- `summary.json`
- `per_seed_metrics.csv`, `per_seed_selective.csv`
- `summary_metrics.csv`, `summary_selective.csv`
- each `seed_*/metrics.json` and `seed_*/selective_prediction.csv`

It does **not** compare PNG plots (raster output) or `versions.json`
(environment metadata). A match means the numerical tables and JSON metrics
are equal within `1e-12`.

## Actual results (this run)

Environment: Python 3.12.10, numpy 2.5.4, pandas 3.1.0, scikit-learn 1.9.1,
matplotlib 3.11.2, pytest 9.2.0.

Mean ± standard deviation over five seeds, **test set only**. These mean/std
values are **descriptive summaries of the five tested seeds**. They are not
confidence intervals and should not be read as inferential uncertainty.

| Method      | Brier score        | Log loss           | Accuracy           |
|-------------|--------------------|--------------------|--------------------|
| raw         | 0.1415 ± 0.0268    | 0.4690 ± 0.0722    | 0.8070 ± 0.0456    |
| calibrated  | 0.1368 ± 0.0224    | 0.4321 ± 0.0546    | 0.8087 ± 0.0419    |
| baseline    | 0.2135 ± 0.0007    | 0.6183 ± 0.0014    | 0.6910 ± 0.0018    |

Findings that were observed, including negative or mixed ones:

- **Proper scores improved across the five tested seeds.** On every seed,
  calibrated Brier score and log loss were lower than raw. The mean
  differences are modest (about 0.005 Brier, 0.037 log loss).
- **Accuracy did not consistently improve.** Mean accuracy is almost unchanged.
  Calibration was slightly better on seeds 42 and 43, and slightly **worse** on
  seeds 44, 45, and 46 (`0.8075` vs `0.808`, `0.8395` vs `0.840`, `0.8525` vs
  `0.853`).
- Both models beat the constant baseline on proper scores and accuracy on these
  seeds. The baseline accuracy is the majority-class rate implied by a constant
  probability below 0.5 (training positive rate ≈ 0.31).
- At threshold 0.90, calibrated mean accepted error was **lower** than raw
  (`0.062` vs `0.090`), and calibrated mean coverage was also **lower**
  (`0.335` vs `0.556`). The lower accepted error is therefore not a
  same-coverage comparison.
- Comparing methods at the same confidence threshold does **not** establish
  superiority at matched coverage. Threshold 0.90 selects different accepted
  subsets for raw and calibrated probabilities.
- The constant baseline has confidence `max(π, 1-π) ≈ 0.69`. Coverage is 1.0
  at thresholds 0.50 and 0.60, and **zero** at 0.70, 0.80, and 0.90. Accepted
  accuracy and error at those higher thresholds are `unavailable`.
- These synthetic results do **not** establish financial performance, LLM
  performance, or validated SI results.

## Limitations

- Synthetic `make_classification` data only; class overlap and label noise are
  controlled by `class_sep` and `flip_y`, not by a real decision process.
- One base learner (GaussianNB) and one calibration method (sigmoid / Platt).
- Five seeds is a small replication set; seed-to-seed spread in scores is
  large relative to the calibration effect. Reported mean/std are descriptive
  of these seeds, not confidence intervals.
- Thresholds were not optimized; the coverage–error curve is descriptive.
- Same-threshold comparisons are not matched-coverage comparisons.
- Reliability diagrams use ten equal-width bins; sparse bins are noisy.
- No claim is made that these numbers transfer to other models, datasets,
  financial decisions, LLM systems, or operational selective-prediction
  systems.

## Your interpretation
Sigmoid calibration improved Brier score and log loss across all five tested seeds, while classification accuracy remained mixed. This shows that improving probability estimates does not necessarily improve the number of correct classifications.

At the 0.90 confidence threshold, calibration reduced accepted error but also reduced coverage. The calibrated model answered fewer cases, so this result does not establish better performance at comparable coverage. A useful next experiment would compare error rates at matched coverage and examine whether the findings hold on a real dataset.
